# Implementation Plan: Dynamic FCM v1 WebPush Notification & Campaign Scheduler

Design and implement a configuration-driven real-time WebPush notification system using Firebase Cloud Messaging (FCM) v1 HTTP REST APIs. This plan avoids backend SDK dependencies and establishes robust matching recommendation alerts, self-healing client-side subscription syncing, and dynamic category-specific landscape visuals.

---

## ⚡ Architecture & Design Decisions

### 1. Zero Backend SDK Dependency (FCM v1 REST API)
We bypass the heavy `firebase-admin` SDK. Instead, we use `google-auth-library` to fetch dynamic OAuth2 access tokens using service account credentials stored in `.env`. Dispatches are made via pure HTTPS POST requests to:
`https://fcm.googleapis.com/v1/projects/${FCM_PROJECT_ID}/messages:send`

### 2. Config-Driven Service Worker Param Injection
Service workers reside in the static `public/` directory and cannot access Node/Next.js environment variables. To keep all keys dynamically driven, we inject Firebase credentials as query parameters during client registration:
`navigator.serviceWorker.register('/firebase-messaging-sw.js?apiKey=...&projectId=...')`
The Service Worker dynamically extracts them on boot using `new URLSearchParams(location.search)`.

### 3. Self-Healing Subscriber Cache
To resolve database resets or token rotations, visiting the website checks if `Notification.permission === 'granted'`. If yes, the global floating bell FAB automatically triggers token fetch and registers it in the backend database.

### 4. Dynamic Category Visual Engine
Push alerts automatically fetch matching Unsplash landscape graphics based on sector keywords (Railways, Banking, Defence, UPSC/SSC, Engineering, Medical, Teaching) in the job details, rather than rendering text-only or generic static images.

## 🗄️ Database Schemas & Collection Specifications

To implement this functionality, three collection documents need to be added to the Mongoose database. Below is their exact structural format:

### 1. Device Push Subscriptions (`notificationsubscriptions` Collection)
Stores the unique, indexed FCM device token generated by the browser, mapped to optional registered user IDs.
* **Collection Name:** `notificationsubscriptions`
* **Document Format:**
```json
{
  "userId": "ObjectId (ref: users, nullable for guests)",
  "fcmToken": "String (required, unique, indexed)",
  "deviceType": "String (default: 'web')",
  "isActive": "Boolean (default: true)",
  "createdAt": "Date",
  "updatedAt": "Date"
}
```

### 2. Administrator Broadcast Campaigns (`notificationcampaigns` Collection)
Stores admin-crafted push campaign templates ready to be polled and executed by our periodic scheduler.
* **Collection Name:** `notificationcampaigns`
* **Document Format:**
```json
{
  "title": "String (required, trimmed)",
  "body": "String (required, trimmed)",
  "image": "String (default: '', optional custom banner URL)",
  "clickAction": "String (default: 'http://localhost:3000')",
  "status": "String (enum: ['draft', 'ready', 'sent'], default: 'draft')",
  "isSent": "Boolean (default: false)",
  "recipientsCount": "Number (default: 0)",
  "sentAt": "Date (nullable)",
  "createdAt": "Date",
  "updatedAt": "Date"
}
```

### 3. Notification History Log / Inbox (`notifications` Collection)
Logs individual notifications dispatched to device tokens to track inbox records.
* **Collection Name:** `notifications`
* **Document Format:**
```json
{
  "userId": "ObjectId (ref: users, nullable for guests)",
  "fcmToken": "String (required)",
  "title": "String (required)",
  "body": "String (required)",
  "clickAction": "String (default: '')",
  "createdAt": "Date",
  "updatedAt": "Date"
}
```

   `🔥 [FCM] Foreground notification received:`

4. **Resiliency Check:** Wipe the database subscriber records. Refresh the homepage tab. Verify the subscriber count in the database automatically heals from `0` back to `1`.
