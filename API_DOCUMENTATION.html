Folder Structure — Every File Explained

jobsarthiapiv2/
├──
index.js Entry Point
Main Express app file. Sets up all middleware and starts the HTTP server.
Contains: compression, cookieParser, CORS setup, route mounting (/web/api), health check endpoint (/health).
Note: Do not run this directly in production — use cluster.js instead.
├──
cluster.js Production Start
Node.js cluster manager. Forks one worker process per CPU core so the server uses all available CPU power.
How it works: Master process forks N workers → each worker runs index.js → if any worker crashes, master auto-restarts it.
Start command: npm start → runs this file.

Project dependencies and npm scripts.
Scripts:
npm start → node cluster.js (production) npm run start:single → node index.js (single process) npm run dev → nodemon index.js (development)

Environment variables. Never commit this file to Git.

├── controller/
│ ├──
authController.js Auth
Handles user registration and login.
Functions:
userSignupController userLoginController
Signup flow: validates input → hashes password (bcrypt, 12 rounds) → generates 6-digit OTP → saves user → sends OTP email.
Login flow: finds user → checks isVerified → compares password → generates JWT (7d) → sets httpOnly cookie.
│ ├──
forgotPasswordController.js Auth
3-step password reset flow using OTP.
Functions:
forgotPasswordController → Step 1: send OTP email verifyResetOtpController → Step 2: verify OTP, return resetToken (15min) resetPasswordController → Step 3: set new password using resetToken
Always returns same message on Step 1 to prevent email enumeration attacks.
│ ├──
userController.js User
Handles user profile and personalized job features.
Functions:
profileController → return logged-in user details Savepreferences → save/update job preferences (upsert) GetSaveData → return saved preferences recommendJobsController → return top 30 matched jobs (scoring engine) toggleBookmark → save or unsave a job (POST /user/bookmark/:jobId) ⭐ New checkBookmark → check if job is bookmarked (GET /user/bookmark/:jobId) ⭐ New getBookmarks → return all saved jobs with full details (GET /user/bookmarks) ⭐ New
Scoring engine in recommendJobsController uses MongoDB Aggregation Pipeline with weighted scoring: education (30pts) + stream (10pts) + location (20pts) + orgType (up to 25pts) + interests (up to 25pts). Minimum score 20 to appear in results.
│ ├──
verifyEmailController.js Auth
OTP verification after signup.
Functions:
verifyOtpController → verify OTP, set auth cookie, mark isVerified=true resendOtpController → generate new OTP, send to email
OTP expires in 10 minutes. After verification, JWT cookie is set automatically so user is logged in instantly.
│ └──
webController.js Main
Core public API handlers. All job portal data goes through here.
Functions:
getJobs → paginated + search + Redis cache getHomePageJobs → limited fields for homepage getJobById → single job full detail getAdmitCard → paginated + category filter + search + cache getResultCard → paginated + category filter + search + cache _getAnnouncement → latest 4+4+4 items JobCategoryController → jobs by domain type getExamCalendar → upcoming exam events (filter by month/year/category) addExamCalendar → add new exam calendar entry (admin) searchJobs → real-time multi-field job search for autocomplete suggestions ⭐ New logutController → clear JWT cookie

Base URL

Local http://localhost:8080/web/api
Production https://api.aspirantcareer.in/web/api
All API routes start with /web/api. The health check endpoint is at /health (no prefix). Protected routes require a valid JWT stored in a httpOnly cookie named token.

Authentication Flow

Signup: POST /userSignup → OTP sent to email → POST /verify-otp → JWT cookie set automatically

Login: POST /login → JWT stored in httpOnly cookie (valid 7 days)

Forgot Password: POST /forgot-password → POST /verify-reset-otp → receive resetToken → POST /reset-password

Protected APIs: The JWT cookie is sent automatically by the browser with every request. No manual header needed.
Public Routes — Search  ⭐ New API
GET /search Public New
Real-time job search API for autocomplete suggestions. Searches across multiple fields simultaneously using a case-insensitive regex. Returns only the fields needed for suggestion UI — making the response lightweight and fast.

Powers: The SearchBar component on aspirantcareer.in homepage. User types → debounce 280ms → this API → suggestion dropdown with domain badges, vacancy count, and last date.
Query Parameters
ParameterTypeRequiredDefaultDescription
q String Required — Search keyword. Empty string returns empty array without DB query.
limit Number Optional 8 Maximum results to return. Hard capped at 20.
Fields Searched (Multi-field OR query)
FieldExample ValuesNotes
title"SSC GD Constable 2025"Primary search field — has DB index
department"SSC", "UPSC", "RRB"Short org name
conductingBody"Staff Selection Commission"Full official name
jobDomains"Railway", "Police", "Banking"Array of domain strings
tags"10th Pass", "Graduate", "SSC"Indexed keyword tags
searchKeywords"constable", "group d"Custom indexed keywords
location"All India", "Uttar Pradesh"Job location field
Filters Applied
• Only isActive: true jobs are returned
• Results sorted by createdAt descending (newest first)
• No Redis caching — search must always return fresh results
• Query timeout protected by MongoDB's default read timeout
Response Fields (Projection — lightweight)
FieldTypeDescription
_idObjectIdMongoDB document ID — used to build the detail page URL
titleStringFull job title
departmentStringShort department name
conductingBodyStringFull conducting organization name
jobDomains[String]Domain array — used for color-coded badges in UI
locationStringJob location
vacancies.totalNumberTotal vacancy count — shown as "X posts" badge
importantDates.applyEndDateLast date to apply — shown as red "Last: DD Mon" badge
Example Requests
GET /web/api/search?q=railway
GET /web/api/search?q=SSC&limit=5
GET /web/api/search?q=UP+police+constable&limit=10
GET /web/api/search?q=bank+po&limit=8

Frontend Flow
SearchBar component (src/components/Search/SearchBar.tsx)

1. User types in search input
2. Frontend debounces 280ms before calling API
3. GET /web/api/search?q={query}&limit=8
4. Dropdown shows up to 8 suggestions with:
   • Matching text highlighted in teal
   • Domain color-coded badge (Railway=blue, Police=orange, Banking=green…)
   • Vacancy count badge (green)
   • Last date badge (red)
5. Click suggestion → navigate to /details/[slug]/[_id]
Performance Notes
• No Redis cache — search results must always be real-time and fresh
• MongoDB index on title field makes regex queries fast
• Projection — only 7 fields returned (not full document) → small payload (~200–500 bytes/result)
• Hard cap at 20 results — prevents expensive large queries
• Frontend debounce at 280ms — reduces API calls while typing

GET /exam-calendar Public
Returns upcoming exam events sorted by date. Can filter by month+year or by category. Default returns all events for next 6 months.
Query Parameters
ParameterTypeRequiredDescription
monthNumber (1–12)OptionalFilter by month. Must be used with year.
yearNumber (YYYY)OptionalFilter by year. Must be used with month.
categoryStringOptionalSSC | Railway | Banking | UPSC | State | Defence | Police | Teaching | PSU | Medical
Logic
• month + year both given → events for that specific month only
• Only category given → upcoming events for next 6 months in that category
• No params → all upcoming events for next 6 months
Example Requests
GET /exam-calendar — all upcoming (next 6 months)
GET /exam-calendar?month=3&year=2026 — March 2026 events
GET /exam-calendar?category=SSC — upcoming SSC events
GET /exam-calendar?category=Railway&month=4&year=2026 — Railway events in April 2026

Model: savedjobs collection — unique index on (userId, jobId) pair prevents duplicate saves.
Frontend behaviour: Logged-in users → API (cross-device sync). Guest users → localStorage fallback.

GET /user/preferencesJobs JWT Required
Returns up to 30 personalized job recommendations based on the user's saved preferences. Jobs are scored and ranked using education, location, organization type, and interests. Only active jobs with open/no application deadline are returned.
Scoring System
SignalPoints
Education level match (cascading — graduate also sees 12th jobs)30 pts
Education stream match10 pts
Location match20 pts
Organization type match (8 pts each, max 25)up to 25 pts
Interest match (5 pts each, max 25)up to 25 pts
Minimum score of 20 required to appear in results. Jobs sorted by score (highest first), then by earliest application deadline.

Admin Routes
POST /admin/exam-calendar Admin
Adds a new entry to the exam calendar. Used by admin to manually add important exam events/dates.
Request Body (JSON)
FieldTypeRequiredAllowed Values
titleStringRequiredAny descriptive title
categoryStringRequiredSSC | Railway | Banking | UPSC | State | Defence | Police | Teaching | PSU | Medical
phaseStringRequiredapplication | lastDate | admitCard | exam | result
dateDateRequiredISO 8601 date string
descriptionStringOptionalShort note about this event
officialLinkStringOptionalOfficial website URL
Phase Values Explained
PhaseMeaning
applicationApplication form opens on this date
lastDateLast date to submit application
admitCardAdmit card will be released on this date
examExam will be held on this date
resultResult will be declared on this date
